# DISARM Explorer

Статическая публичная витрина фреймворка DISARM.

## Что это

Локализованный обозреватель фреймворка DISARM:

- обзор и фазы кампании;
- матрица атак;
- матрица защиты;
- поиск по объектам;
- каталог инцидентов;
- конструктор плана реагирования;
- модальные карточки с перекрестными связями.

## Production

- domain: `https://disarm.qdev.run/`
- edge host: `148.230.117.131`, static root: `/var/www/disarm.qdev.run`
- serving origin: `187.55.228.239:18080`, static root: `/srv/www/disarm.qdev.run`
- backups: `/var/www/disarm.qdev.run-backups/<UTC timestamp>/` on edge and `/srv/www/disarm.qdev.run-backups/<UTC timestamp>/` on origin
- file owner after deploy: `www-data:www-data`
- unauthenticated root: `302 /login` via the server-side PIN session boundary; the allowlisted provenance and AVDS contracts remain public and contain no credentials or personal data

The edge vhost serves allowlisted static contracts locally but proxies the protected document root to the origin. A release therefore requires both hosts to be reachable, snapshotted and hash-aligned. Never update only the edge while the origin is unavailable: that would mix one source candidate with a different protected HTML/runtime surface.

## Deploy contract

Перед любым обновлением production roots:

1. Проверить оба serving host:
   - edge и origin доступны по авторизованному SSH;
   - у каждого достаточно свободного места для snapshot и новых файлов;
   - active edge vhost всё ещё проксирует защищённый root к ожидаемому origin.
2. Создать snapshot на обоих host:
   - сохранить timestamped backup текущих production-файлов до любых записей.
3. Заливать только измененные публичные файлы на edge и origin как единый candidate:
   - `index.html`
   - `assets/app.js`
   - `assets/avds-disarm-adapter.css`
   - `assets/avds-static-token-contract.css` and `assets/avds-static-preview-bundle.css` when the source candidate references them
   - AVDS-контракты в `data/avds-*.json` и `data/disarm-provenance.json`
   - `data/platform-capabilities.json`
   - `release.json` generated by `python3 scripts/build_release_receipt.py`
   - `health.json` generated alongside the release receipt (static content health, not process liveness)
   - `assets/style.css`, `data/disarm.json`, `favicon.svg`, `robots.txt`, `sitemap.xml` только при отдельном изменении
   - `favicon.ico` генерировать из canonical `favicon.svg` командой `./scripts/build_favicon_ico.sh`; он нужен для server-side `/login` boundary
   - `README.md`, `docs/*` и `scripts/*` держать в локальном source tree и ops-контуре, но не открывать их наружу как публичные маршруты
   - не оставлять в `production root` резервные файлы вида `*.bak*`

`release.json` и `health.json` намеренно не входят в `manifest.artifacts`: иначе receipt включал бы собственный hash. Их нужно всегда добавлять к manifest-derived allowlist; это также закреплено в `deployment_contract.required_publish_files`.
4. После загрузки вернуть владельца:
   - `www-data:www-data`
5. До завершения release выполнить `check_runtime_evidence.py`, `smoke_live.sh` и public browser proof; rollback выполнить из snapshots при любом source/runtime mismatch.

Локальная рабочая копия должна хранить полный каталог `fonts/avds/`, иначе preview на `python3 -m http.server` даст ложные 404 по шрифтам при том, что production уже корректен.

## Локализация

Модуль использует двухслойную русификацию:

1. `index.html`
   - перевод всех пользовательских элементов интерфейса;
   - русские названия разделов, кнопок, экспортов и ссылок в footer.

2. `assets/app.js`
   - `LOCALIZED_NAMES` для ручного русского слоя тактик, техник, контрмер и названий инцидентов;
   - `LOCALIZED_SUMMARIES` для демонстрационных русских описаний ключевых объектов;
   - `LOCALIZATION_GLOSSARY` для широкого fallback-перевода видимых имен и описаний.
   - `previewSummary()` для чистого русского preview-слоя там, где исходный корпус содержит длинные англоязычные summary.

Это значит, что:

- UI уже русифицирован;
- слой тактик и техник полностью русифицирован;
- слой контрмер получил расширенную ручную русификацию названий;
- каталог инцидентов показывает локализованные названия и русские preview-описания;
- карточки техник и результаты поиска показывают русский preview-слой вместо длинных исходных англоязычных summary;
- исходный корпус DISARM полностью не переписан вручную и при необходимости может быть переведен отдельным data-pass.

## Ограничения

- Полный литературный перевод всего корпуса `data/disarm.json` пока не сделан.
- STIX / Navigator export оставлены в англоязычном техническом формате, потому что это машинные артефакты интеграции.
- Текущий публичный режим покрывает `DISARM 1.x core`, сверенный с официальной сгенерированной SQLite-базой. DISARM 1.7 и DISARM 2.0 Observations/Assessments не смешиваются с этой матрицей и требуют отдельного data-pass/экрана.
- Лицензия публично указана как `CC-BY-SA-4.0`, согласно текущим `LICENSE.md` официальных репозиториев DISARM Foundation.

## Контракт зрелости AVDS

Публичный шильдик показывает не маршрутное подключение, а общий показатель зрелости системного контракта из десяти равновесных категорий. Непроверенное требование получает ноль, частично подтверждённое — половину балла.

- `data/avds-system-contract.json` фиксирует версию и происхождение AVDS, хеши подключённых файлов, локальные отклонения, токены, темы, компоненты, состояния, композиции, адаптивность, визуализацию данных, доступность, контент и QA.
- `data/avds-coverage.json` содержит расчёт по категориям и доказательства/разрывы каждого критерия.
- `data/avds-component-contracts.json`, `data/avds-responsive-contract.json`, `data/avds-locale-contract.json` и `data/avds-data-visualization-contract.json` — машиночитаемые реестры компонент, ширин, локализации и визуализации.
- `data/disarm-provenance.json` — паспорт корпуса DISARM, лицензия, происхождение и ограничения интерпретации.
- прежние 20/20 сохранены внутри `route_coverage` и не подменяют общий показатель.
- `qz.energy` не является этим consumer: его отклонения должны измеряться отдельным контрактом на собственном публичном и исходном контуре.

При обновлении AVDS сначала обновляются upstream identity и хеши, затем пересчитываются все категории fail-closed, выполняются статические и браузерные проверки и только после этого меняется публичный шильдик.

## Локальная работа

Простой локальный просмотр:

```bash
cd <local-disarm-explorer>
python3 -m http.server 4187
```

Быстрая проверка статического слоя:

```bash
./scripts/smoke_static.sh
```

Отдельная строгая проверка HTML- и data-integrity:

```bash
python3 scripts/check_integrity.py
```

Проверка включает:

- целостность `data/disarm.json` и связей между объектами;
- наличие и корректность локальных asset-ссылок из `index.html`;
- базовую проверку `robots.txt` и `sitemap.xml`.

Проверка live-контура и закрытых служебных маршрутов:

```bash
./scripts/smoke_live.sh https://disarm.qdev.run
```

Контракт границ интеграции с Qdev Platform (не заменяет обязательный `qdev-project.json`) проверяется так:

```bash
python3 scripts/check_platform_contract.py
```

Root `qdev-project.json` валидируется against vendored exact `contracts/qdev-project-manifest-v1.json` (Platform schema SHA-256 `95529bcb534b0b9b20b53fa24e93e3ebeafdba640cff9d99540026fcfbf2ab26`). The schema copy is a local validation dependency; the authoritative catalog remains Platform Portal.

Content-addressed release receipt:

```bash
python3 scripts/build_release_receipt.py
python3 scripts/build_release_receipt.py --check
```

После отдельно авторизованного release, но до объявления production-паритета, необходимо выполнить fail-closed сверку source и публичных контрактов:

```bash
python3 scripts/check_runtime_evidence.py --base-url https://disarm.qdev.run
./scripts/smoke_live.sh https://disarm.qdev.run
```

Пока первая команда сообщает `RUNTIME_EVIDENCE_CONFLICT`, candidate и runtime нельзя называть одним релизом.

## CI

Переносимые определения CI лежат в `.github/workflows/`:

- `source-quality.yml` запускает только source-contract gates на push, pull request и вручную;
- `release-evidence.yml` запускается только вручную после публикации и fail-closed проверяет public parity, затем live smoke.

Наличие YAML не является доказательством запуска CI: до появления канонического Git remote и первого сохранённого run этот контур остаётся документированным, а не подтверждённым.

Изолированная regression-проверка release gate входит в `./scripts/smoke_static.sh`: она подтверждает и совпадающий runtime contract, и fail-closed реакцию на adapter drift.
