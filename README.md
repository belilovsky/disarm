# DISARM Explorer 1.7

Обозреватель официального DISARM 1.7.0 SQLite core с защищённым PIN-доступом: обзор, матрицы атак и защиты, поиск, инциденты, план реагирования и справка.

## Источник и локализация

Повторяемый импорт: `python3 scripts/build_corpus.py --check`. Скрипт использует SQLite из коммита `216a8828c7d0f6a67ad2a8867c716bf961914776` официального `DISARMFoundation/DISARMframeworks-17`, проверяет SHA-256 `753eef8df1ce9678c41e16f7f45ccc59fce095c7be00f81f832be689bf43ad38` и явно учитывает исключения ссылок на отсутствующие объекты, включая T0005. Паспорт: `data/disarm-provenance.json`.

Авторский интерфейс, справка, доступные подписи, состояния, уведомления и текстовые отчёты переведены на RU/KK/EN. Приоритет языка: `locale=ru|kk|en` в URL → сохранённая настройка → RU. Язык сохраняется в ссылках на вкладки, карточки, плейбук и возврат после входа.

Официальные названия и описания сохраняют исходную формулировку. Старые русские пересказы исключены из отображения: для них нет привязанной к корпусу редакционной сверки, а C00006 содержал смысловое несоответствие. Новая запись в словаре официальных переводов допустима только после проверки всей записи против зафиксированного источника. Пользовательские заметки не переводятся.

Корпус: 4 фазы, 13 тактик, 71 техника, 140 контрмер, 63 инцидента, 14 метатехник, 95 индикаторов, 42 задачи, 151 инструмент и 43 примера. Примеры пока не представлены отдельным экраном. Полный перевод корпуса, архив 1.x и Observations/Assessments 2.0 — отдельные программы.

Атрибуция и CC-BY-SA-4.0 сохранены в интерфейсе и экспортах. Navigator/STIX сохраняют исходные названия и совместимые идентификаторы; авторские подписи следуют выбранному языку.

## Работа и проверки

Python 3.12 и Node.js 22; зависимости валидатора устанавливаются в отдельное виртуальное окружение:

```sh
python3 -m venv .venv-release
.venv-release/bin/pip install -r requirements-release.txt
export PATH="$PWD/.venv-release/bin:$PATH"
python3 -m http.server 4187
```

Обязательная проверка публикации: `./scripts/smoke_static.sh`. В неё входят воспроизводимость корпуса, словарь, кеш, неизвестные ID, PIN-контракт, три экспорта на трёх языках, строгий STIX 2.1, целостность AVDS и платформенных контрактов, release receipt и существующие три регрессии. Дополнительные отдельные наборы не требуются.

Кеш принимается только после проверки той же схемы и SHA-256 корпуса, что и сетевой ответ. Несовместимый кеш отклоняется. URL и локальный выбор объединяются, затем нормализуются по существующим техникам; неизвестные ID исключаются из всех счётчиков и экспортов с уведомлением.

## Эксплуатация

- Сайт: https://disarm.qdev.run/
- Edge: `148.230.117.131`, serving root `/var/www/disarm.qdev.run`.
- Origin: `187.55.228.239:18080`, serving root `/srv/www/disarm.qdev.run`.
- Исходники: https://github.com/belilovsky/disarm, ветка `master`.
- PIN-сервис: `ops/auth/`; systemd и nginx: `ops/auth/disarm-pin-auth.service`, `ops/nginx/`.
- Секреты: существующий защищённый `/etc/disarm-pin-auth.env` на каждом хосте; в репозиторий и журналы не включаются.
- `/health.json` — статическая идентичность содержимого; `/runtime-health.json` — свежая проверка PIN-процесса, релиза, критических файлов и содержимого корпуса.
- Frontend home: сам обозреватель; запись Platform — `Platform#data` и `/docs/project?id=disarm`, продуктовый и технический владелец QDev, данные DISARM Foundation. Статусы эксплуатации должны ссылаться на реальные проверки.

Сериализованный двуххостный процесс: [ops/README.md](ops/README.md). Режимы `preflight`, `publish`, `verify`, `rollback`; manifest-derived allowlist, две блокировки, повторная сверка актуальной базы под блокировками, снимки и атомарное переключение serving roots. Прежний каталог сохраняется для восстановления. Публичные служебные пути закрыты.

## AVDS и готовность

AVDS 4.7.0, адаптер 1.3.10. Режим композиции `preserve`: существующие tabs, inputs, chips, cards, tables, dialog и состояния. Новый примитив и миграция не нужны.

Текущий протокол: [docs/PREPRODUCTION_1_7.md](docs/PREPRODUCTION_1_7.md). Машинные контракты: `data/avds-*.json`, `/.well-known/avds-adoption.json`, `qdev-project.json`, `release.json`.

Локальные проверки, runtime, публичный браузер, GitHub CI и независимая визуальная оценка — отдельные подтверждения. YAML workflow не доказывает запуск. При блокировке GitHub Actions по оплате допускается ручной выпуск точного проверенного коммита с явным статусом отсутствия provider CI. Независимая визуальная оценка пока `needs visual review`.
